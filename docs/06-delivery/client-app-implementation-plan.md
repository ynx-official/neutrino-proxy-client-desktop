## 1. 执行原则

先验证兼容性最难的部分，再投入完整 UI。每阶段用可观察行为验收，保留原 Java 客户端作为参考，不覆盖现有服务端、管理后台或其构建流程。所有正式说明继续放在根目录 `docs/`，实现代码位于独立的 ``。

本文件是具体设计提案的一部分。2026-10-15 用户进一步授权开始重写，直到软件能打开且页面与样图一致；当前实施记录见[开发进展](client-app-development-status.md)。完整迁移仍按阶段验收，用户已确认的平台、范围和技术路线不再重复询问。

## 2. 阶段与完成条件

| 阶段 | 工作内容 | 可审阅产物 | 完成条件 |
|---|---|---|---|
| 0：设计收敛 | 审阅单连接、关闭窗口、启动选项、凭证与日志策略、UI 风格 | 已确认规则清单和更新后的设计文档 | 已批准内容与待验证事项明确区分 |
| 1：兼容性原型 | 提取协议样本；验证 Rust 认证、TLS/JKS 导入；搭建最小测试对端；测量 Java 与 Rust 基线 | 协议黄金样本、TLS 矩阵、资源报告 | 能解释全部关键兼容差异，不依赖用户 Java 环境 |
| 2：工程基础与 TCP 切片 | 建立独立 Cargo / npm 工程、CI、编解码器、配置、认证、心跳、TCP 转发、停止 | 可无界面运行的客户端内核和测试 | TCP 双向传输正确；慢连接受限；断开可回收；测试先失败后通过 |
| 3：UDP 与异常切片 | UDP 会话、端口池、超时、响应次数、隧道复用、重连竞态 | 完整核心行为与故障回归测试 | 通过对应兼容矩阵，资源不串用、不泄漏 |
| 4：桌面宿主与配置切片 | Tauri、系统安全存储、原子配置、托盘、单实例、窗口创建销毁 | 可启动并后台运行的桌面包 | 无窗口时仍连接；打开窗口只恢复视图；退出清理所有任务 |
| 5：可交互界面 | 按已选风格实现连接、日志、设置与导入预览 | 三页可运行 UI、组件和流程测试 | 通过 UI 核心场景与视觉检查；不将秘密写入前端持久存储 |
| 6：长期运行与分发 | Windows/macOS 构建安装、资源测试、72 小时运行、签名与发布材料 | 安装包、测试报告、操作说明、已知限制 | 达到已批准的性能预算，兼容差异已确认，正式发布单独审批 |

阶段 1 的原型只服务兼容性验证；若要进入正式工程，需要经过结构和测试审查，不自动把临时代码复制为生产实现。阶段 2–5 的每个行为切片均先写能失败的测试，再实现和验证。

## 3. 优先级与工作量判断

按风险优先级：TLS/JKS 与协议 → TCP 背压和生命周期 → UDP 会话 → 配置与身份迁移 → 桌面窗口生命周期 → UI 与打包。界面可以用状态替身验证交互，但不应以此跳过内核兼容门槛。

当前只能判断为中等偏大的独立客户端工程，不能可靠给出固定完成天数。影响工作量的最大变量是旧证书兼容、非默认配置覆盖和 Windows/macOS 长期运行问题。阶段 1 完成后，根据已验证差异给出后续阶段的工作量区间，避免把“连通演示”的时间当成可替代客户端的交付时间。

## 4. 测试与 CI 基础

- Rust：`cargo test` 验证协议和状态机，集成测试使用可控制的本地 TCP/UDP 对端；必要时使用属性测试和模糊测试检查长度解析。编译器检查、格式化和 lint 纳入 CI。
- Vue：Vitest + Vue Test Utils 验证界面行为，Playwright 检查用户流程；IPC 测试替身与真实桌面运行结果分别记录。
- Windows/macOS：分别构建 Release 包并执行原生检查；平台自动化不可用的部分记录可重复的人工验证步骤，不把跳过标记为通过。
- 依赖：只在首次工程初始化或声明变化时安装，锁定版本；不修改旧管理后台依赖。

具体命令由实际工程脚本定义，以上是拟定流程，不代表已执行的命令或已建立 CI。

## 5. 分发与交付建议

建议首批验证 Windows x64、macOS Apple Silicon；macOS Intel 根据可用测试设备并入支持矩阵，是否作为首版硬性目标在设计审阅时确认。Windows ARM64、Linux 暂不自动扩展。

Windows 安装程序需处理 WebView2 运行时条件，macOS 应用使用系统 WebView；最终用户不安装开发工具或 Java。具体打包选项以 [Windows 安装文档](https://v2.tauri.app/distribute/windows-installer/)和 [macOS 应用包文档](https://v2.tauri.app/distribute/macos-application-bundle/)为准。安装包签名、公证、发布渠道及相关费用由用户确认后执行，不在设计阶段自动购买或发布。

初期提供手动安装升级；新版本保留配置和身份，迁移失败不得覆盖旧数据。卸载默认保留用户配置与日志的建议需在隐私与删除规则审阅中确认；不提前实现静默删除。旧 Java 客户端和配置保持可恢复，但同一 License 的新旧实例不应为对比测试而无计划同时启动。
