## 1. 核心用户场景

| 编号 | 前提 | 操作 | 必须观察到的结果 |
|---|---|---|---|
| U01 | 全新安装且未保存配置 | 打开 App | 显示填写与导入入口，不擅自连接 |
| U02 | 填写有效连接参数 | 保存并连接 | 经校验、连接和认证后进入已连接，不要求 Java 或命令行 |
| U03 | 端口非法或 License 为空 | 点击连接 | 定位字段错误，不创建网络会话 |
| U04 | 已连接 | 关闭窗口，再从托盘打开 | 转发继续；重建 UI 显示同一会话，只有一个引擎 |
| U05 | 网络断开且允许重试 | 等待重连后恢复网络 | 按配置策略恢复，不产生多个重连循环 |
| U06 | 处于重连等待或认证中 | 点击断开 / 取消 | 全部旧任务退出，网络恢复也不自行重连 |
| U07 | 认证失败且 unlimited=false | 发起连接 | 停止本次连接，保留 App 和修改入口 |
| U08 | 已连接且有未保存修改 | 选择保存，下次生效 | 当前会话不被中断，清楚标明待生效配置 |
| U09 | 已连接且保存新配置 | 选择保存并重连 | 先清理旧会话，再用新版本连接 |
| U10 | 某个本地目标不可达 | 触发该目标的转发 | 显示目标错误；健康控制通道不误标为全局掉线 |
| U11 | 旧 YAML 含缺失变量或不存在的证书路径 | 导入 | 跳过对应项，保留原值并列出跳过项，其他可用字段继续导入；不修改原文件 |
| U12 | 日志含模拟凭证和载荷 | 查看与导出 | 常规日志不暴露凭证、密码或载荷，文件容量受限 |
| U13 | 活动连接存在 | 用户确认退出应用 | socket、重连、UDP 绑定释放，进程结束 |
| U14 | 设备睡眠后恢复或更换网络 | 观察自动恢复 | 旧状态不假报健康，按策略恢复且可手动停止 |
| U15 | 窗口恢复过程中会话恰好断开或认证完成 | 打开窗口并注入对应状态变化 | 最终视图与 Rust 状态一致，不因快照与订阅竞态停留在旧状态 |
| U16 | 缺少 tunnel、只有协议 / UDP 配置 | 导入并确认 | 不报分组缺失，应用有效字段，保留已存地址和凭证，不自动连接 |
| U17 | 首次配置仅包含部分有效字段 | 导入并确认 | 可保存部分配置；缺失的地址 / License 仍在连接前要求补齐 |
| U18 | 无有效字段 / 无关 YAML | 导入 | 只提示未发现可导入配置，不能应用；不报分组缺失或修改原值 |
| U19 | 有效字段与自定义协议项混合 | 导入 | 水位线、空闲与合法拆包参数可预览、保存并在新连接生效；无效字段保留原值并列为跳过项（2026-10-26 修订） |
| U20 | 旧官方连接配置位于 neutrino.proxy.client | 导入 | 识别地址、端口、SSL、License、证书及密码，允许确认；无需 tunnel 分组 |
| U21 | 本机已有地址与 License，但文件无可用字段 | 查看预览 | 不显示本机地址 / License 作为文件内容，应用禁用；部分导入也只列实际读取字段 |
| U22 | 主窗口已关闭、托盘仍运行 | 单击 / 右击托盘 | 直接显示系统原生菜单，不创建托盘 WebView；Escape 和点击外部按系统行为收起 |
| U23 | 只有日志、时长或 revision 改变 | 状态订阅更新 | 复用现有菜单；状态 / 地址变化才更新，互斥动作和脱敏摘要保持正确 |
| U24 | 原生托盘任意连接状态 | 打开菜单 | 无应用标题和“状态：”前缀；状态带小图标且可打开连接页，服务器禁用；动作带图标、仅两个分隔线，连接 / 断开互斥 |
| U25 | 已安装前端依赖且开发端口空闲 | 在 App 目录执行 cargo run | 自动启动 Vite，页面就绪后打开桌面；正常退出或终止父进程后释放自有服务端口 |
| U26 | 开发端口已有本项目 Vite / 其他服务 | 执行 cargo run 后退出 | 本项目服务复用且不被结束；其他服务明确报端口占用且保持运行 |
| U27 | 尚未安装前端依赖 | 执行 cargo run | 打开窗口前提示 npm ci，不自动安装或留下前端子进程 |
| U28 | 默认应用设置 | 进入“设置 → 应用设置” | 两项默认关闭；读取期间禁用，开关更改自动保存，刷新仍显示已保存 / 系统状态 |
| U29 | 连接配置有未保存修改 | 切换应用设置页签 | 取消后草稿保留；确认放弃后进入应用设置 |
| U30 | 系统注册或文件写入失败 | 更改相应开关 | 不显示虚假的保存成功；显示错误并回读当前状态，连接配置与凭证保持原样 |
| U31 | 自动连接已启用、配置完整 | 完整退出后重新启动进程 | 自动发起一次初始连接；网络或认证失败后停止，不受 unlimited 覆盖；成功后断线仍按原策略重连 |
| U32 | 自动连接已启用、配置不足或凭证读取失败 | 启动后补全 / 导入配置，或打开托盘窗口 | 启动跳过；这些操作不会补触发自动连接，用户仍可手动连接 |
| U33 | 启动任务尚未运行，或已尝试过 | 手动断开 / 重建窗口 / 再次启动同一程序 | 不被迟到启动任务重新连接；同一进程最多消费一次启动机会 |
| U34 | Windows / macOS 已安装 App | 分别开启与关闭开机自启并重新登录 | 系统注册状态准确，路径含空格仍可启动；关闭后不再自动运行。此项包含实际登录验证，不由注册接口单测替代 |

## 2. 兼容性验证

2026-10-26 新增[七项同步验收矩阵](../03-architecture/client-app-java-compatibility.md#七项对应关系)：含 1025 活动连接、写缓冲迟滞、TCP/UDP 读超时、写空闲心跳、全空闲控制、Java 拆包向量、旧 ID 迁移、TLS 名称与签名验证。导入之后再次保存必须保留新协议字段与旧 ID，不能被之前未保存的表单覆盖。执行结果见开发记录，不据此宣称下方所有长期或平台场景已通过。

协议测试采用旧 Java 编码器生成的固定字节样本和独立断言，不只用新编码器喂新解码器做自我验证。覆盖每种实际使用的消息、空 info/data、中文、二进制零字节、半包、多包、边界长度、错误长度及未知类型。保留样本生成方法和对应源码版本。

建立客户端测试对端模拟控制与数据隧道，不依赖修改生产服务端；允许在独立测试环境用现有服务进行互通验证。每个兼容测试记录旧客户端结果、新客户端结果和差异原因。

| 范围 | 必测情形 |
|---|---|
| 认证 | 成功、失败、重复连接错误、附加 JSON 字段、保持 clientId |
| TLS | SSL 开关、自定义和内置信任证书、JKS 密码错误、过期、未知信任根、主机名差异、算法兼容 |
| TCP | 双向随机数据校验、并发、多次复用、目标拒绝、读写错误、慢接收方、断开清理 |
| UDP | 数据报边界、访客/目标隔离、0 次与 -1 次响应、非正超时、再次发送重置计数、双向活跃续期、端口范围端点与保留端口、耗尽后单向退化及告警、回收复用 |
| 配置 | 完整旧样本、缺失字段、环境变量占位、非默认帧参数、线程参数映射、未知字段、原子保存失败 |
| 生命周期 | 快速连接/断开、重复点击、旧任务迟到、窗口重建、进程再次启动、退出时有活动传输 |

对 TLS、线程配置和载荷日志等已识别的差异，先完成明确决策和验收规则再宣称兼容。不能用关闭证书验证、删除失败用例或将被跳过字段声称已兼容来获得通过。2026-10-16 用户已要求导入跳过无效 / 不支持项，导入验收与网络协议兼容验收分别记录。

UDP 回收测试需同时创建一个长期活跃会话和多个随后到期的会话，确认活跃会话不会阻挡其他端口回收；这覆盖现有扫描器只检查首项的缺陷。未知消息测试区分“帧结构合法但无处理器”和“长度或结构损坏”，分别验证兼容忽略与协议错误处理。

## 3. 内存与性能测量

每个平台使用 Release 构建，记录硬件、系统、WebView、Rust、依赖版本及配置。分别测试 Java 基线、Rust 内核、完整 App；同机同配置同负载，避免拿 Java 调试构建与 Rust Release 比较。

至少记录以下场景，每 5 秒采样并保存原始数据：

1. 断开且窗口打开，空闲 10 分钟。
2. 已连接且窗口打开，空闲 30 分钟。
3. 已连接并关闭窗口，空闲 30 分钟，核对整个进程树。
4. 1、10、100 个 TCP 连接与等量 UDP 会话（不足容量时如实记录），固定负载持续 30 分钟。
5. 慢接收方和突发数据，验证内存不会随排队数据无限增长。
6. 窗口开关 100 次，连接断开 100 次，检查任务、句柄、socket 和内存趋势。
7. 72 小时混合负载与定期断网恢复，停止负载后再空闲 30 分钟观察资源回收。

Windows 分别记录进程树私有字节与工作集，macOS 记录 memory footprint 与 RSS；跨平台不把不同指标直接当成同一个数。统计包括 Rust 主进程及本 App 的 WebView 辅助进程，注明无法归属的共享系统开销。记录 P50、P95、峰值、CPU、吞吐、延迟、线程、句柄和实际成功连接数。

**建议的初期评审门槛：** 后台空闲占用应明显低于相同配置的 Java 基线；连续运行不存在持续向上且不回落的资源趋势；慢连接内存受预算约束；相同负载下吞吐不能以明显退化换取低内存。固定 MB 上限和允许的性能差异，在兼容原型测出基线后由用户确认并写入版本化验收记录，当前没有已批准的数值承诺。

出现内存增长时先区分正常缓存、分配器保留和泄漏；必须结合有界状态计数、重复稳定负载及空闲恢复作结论，不能只看单次任务管理器截图。

## 4. UI 与桌面平台验证

组件和路由状态使用 Vitest + Vue Test Utils；浏览器流程使用 Playwright 与明确标记的 IPC 测试替身，覆盖表单、错误、日志筛选与配置待生效。浏览器通过不替代 Tauri 原生验证。

Windows 和 macOS 分别验证安装、首次启动、托盘、窗口关闭与恢复、开机/登录启动权限、退出、卸载和升级保留配置。macOS 的原生 WebView、菜单栏及签名场景必须在 macOS 环境中检查，不能用 Windows 截图代替。

视觉检查包含最小尺寸、常用窗口、不同缩放、长内容、焦点、禁用、加载、空态与错误。概念样图人工核对与界面规则一致，不计为可运行 UI 的验收证据。

## 5. 证据与交付判定

各阶段保留命令、环境、退出码、测试报告与失败项。最终交付至少包含协议兼容矩阵、配置迁移样本、TLS 差异决策、双平台运行记录、72 小时资源曲线和安装包验证结果。
