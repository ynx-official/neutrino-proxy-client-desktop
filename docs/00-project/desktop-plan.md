状态：Review

## 已确认需求

用户选择纯 Flutter/Dart 方案，在 `D:/study/neutrino-proxy-client-desktop` 独立实现。网络协议和业务行为直接依据官方 Java 客户端及 core；既有 Rust/Tauri/Vue App 仅作为界面布局参考。面向需要在 Windows/macOS 长期运行隧道的用户，提供连接、日志、设置三页及托盘入口。

## 流程与边界

首次启动 → 填写或导入连接参数 → 保存 → 连接和认证 → 展示实时状态 → 断开/重连；关闭窗口保留连接，从托盘恢复。保存的新配置在下次连接生效。端口映射继续使用既有后台。无新服务端、账户体系、计费或管理端。

UI 沿用 860×620、白色画布、顶部导航、细线与项目 Logo。使用 Flutter 内置控件定制尺寸、主题、焦点和错误状态。系统窗口及托盘插件仅负责平台集成，不承载网络业务。

## 实施选择

2026-10-16 用户追加“后台明显降低占用、网络内核独立运行、收起真正释放界面”的目标，并要求先规划。对应[架构提案](../03-architecture/background-process-design.md)和[分阶段计划](../06-delivery/background-process-plan.md)均为 Review，尚未实施；以下仍记录当前实现。

纯 Dart 协议/证书/配置模块 → 长期 isolate 内的异步连接引擎 → Riverpod 状态适配 → Flutter 页面 → 桌面窗口与托盘。只向 UI 传状态和有界脱敏日志，不传业务载荷。普通配置用版本化 JSON，凭证用系统安全存储，首版不引入数据库。

## 验收切片

1. 工程与测试：锁定 Flutter/Dart 和依赖，创建 Windows/macOS 工程与 CI。
2. 协议：固定字节向量、半包、多包、Unicode、非法长度和最大帧边界。
3. 内核：认证失败分类、取消与重连、TCP 双向转发、UDP 响应次数/超时/端口释放、TLS/JKS 读取。
4. 应用：配置校验与保存、脱敏日志、三页布局、未保存离开确认、托盘与关闭后恢复。
5. 验证：执行 analyze、测试、Windows 构建和可行的运行检查；macOS 原生交互、真实服务端互通及长期资源测试单独记录，不以本地模拟通过替代。

## 明确限制与风险

两种语言的线程配置不能一一对应，导入时展示说明；不支持的非默认协议字段必须阻止应用。TLS 的证书链、主机名与有效期验证保持开启，Java 旧实现未显式启用主机名检查的差异必须明确展示。Java 在认证失败时停止进程，桌面端仅停止连接并保留修正入口。原用户文件保持原样；不自动连接真实服务器。

当前批准的是技术路线与参考来源，未承诺固定内存数值、72 小时稳定性、macOS 实测结果或正式发布。
